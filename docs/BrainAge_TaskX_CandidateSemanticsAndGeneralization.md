Both recognition buffers have capacity **16 uint16 slots**. The worker loops over at most **15 nonzero codes** per group, stopping at NUL. The numeric consumer takes at most **16 combined positions** from retained prefix plus current suffix. The raw recognizer counts are distinct from storage capacities and emitted code length: extraction can emit a representation string for a segment. In all Task X samples, the raw counts equal the measured code lengths. No generic Unicode/rank semantics are claimed.

The secondary accessor is `020A3FFC(context,group,index,buffer,16-index,null,null)`. It resolves the same segment via `020A3ACC`, then invokes `020A4B24` with its alternate-representation switch; the alternate path is `020A49B8`, while primary extraction uses `020A4A1C`. The worker ultimately consumes the first returned code per position. Calling this a **secondary representation** is mechanical; neither ?second-best ranked candidate? nor a probability is proven. The production service exposes precisely that first code, without enumerating private recognizer hypotheses.

With policy 2 and a nonnegative expected value:

- One output position and expected <10: replace the primary digit only if the secondary equals expected and is not 1.
- Two output positions and expected >=10: compare secondary positions to expected tens/units and substitute matching positions. The units branch unusually checks **secondary tens !=1**; the offline model preserves this exact guard.
- Other output lengths do not get these substitutions. Finding an expected digit somewhere in `51`/`47` is not candidate-set acceptance.

The worker also calls `020A3FB8` for per-position metrics and `020A3F2C` for contributing stroke identifiers/counts. Numeric selection does not rank by those metrics. Contributor counts affect a narrow three-stroke/two-digit 4-or-5 delay case. Internal flags exist in segment nodes; no extra public rank/flag array is used by this numeric consumer. Metric remains diagnostic, without a confidence interpretation.

After selection, ordinary numeric mismatch uses countdown 41; matching single-digit 7/9 uses 1 and can publish in the same update. Matching 4/5 after one stroke can use 11. Task X models numeric selection offline, not elapsed updates, queues, rendering or live submission. It is incorrect to reinterpret W's final scalar 8/10 as original-game answer accuracy; the W corpus and reported scalar results remain unchanged.

## Input preprocessing and miss classification

The original accumulator `02052424..020525F0` selects an enabled rectangle at initial contact, samples once per update including held duplicates, clamps coordinates to the rectangle, stores `(y,255-x)` as two uint16 fields, and finalizes a nonempty count/pointer descriptor on release. No title-side decimation, smoothing, reversal, bounding-box normalization, scale/translation beyond that transform, pen-up sentinel, or timing/contact payload intervenes. At least one point is sufficient for descriptor creation. Limits are 4096 total points/32 descriptors. `0205204C` queues the descriptor index; the worker passes the same descriptor directly to `020A41A0`.

Inside the original boundary, `020A4718` calls conversion `020B387C` with internal point limit 32 and stored configuration offsets/shift. That original internal processing still executes in the service; it should not be duplicated in the host. No missing external preprocessing step was proven and no input change was made. Known differences are host duplicate suppression and canvas rejection versus original rectangle clamping. Neither is hidden: all X coordinates avoid the rectangle discrepancy; S's 9/5 versus 5/3 comparison proves duplicate equivalence for known 4 only. Arbitrary sampling-density effects are not universally ruled out.

**W-7:** combination, with strong evidence for stroke-boundary/segmentation sensitivity on fixed geometry and a production-consumer semantic mismatch. Joining bar+diagonal produces 7, with or without the separate crossbar; keeping them separate yields 5/51. Moving the crossbar first does not fix it. The original complete final number is 51, while scalar 5 truncates it. Expected-aware original publication would instead occur at the first 1/7 release. This is not proof of a recognizer-wide inability to recognize 7, nor a final ranked-set rescue.

**W-9:** combination, with strong evidence for stroke-boundary sensitivity and additional direction sensitivity. Joined identical loop/tail gives 9; reversed loop gives 0; tail-first still gives 4. The original final numeric value for the W anchor remains 4, but its first 0/9 release selects expected 9 and is immediately publishable. No final candidate-set rescue exists. A missing preprocessing explanation is not supported by this bounded inspection; genuine ambiguity remains a reasonable description of individual separated forms, not the best sole explanation of the experiment.
